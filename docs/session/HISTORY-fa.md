## به‌روزرسانی وضعیت: مانیتورینگ ۲٫۷
کاربر مسیر درخواست رسمی داده را نپذیرفت و ارتقای همان سیستم مانیتورینگ را خواست. جریان پیشنهادی فعلی Start.cmd نسخهٔ ۲٫۷ است: بدون CA/پروکسی/درخواست کلید، با گزارش یکپارچه، شمارندهٔ ورودی/خروجی و دسته‌بندی تغییرات لاگ محلی همان اجرا. مسیرهای TLS قدیمی زیر فقط تاریخچه‌اند. ثبت محلی مشخصات اثبات ارسال نیست؛ دادهٔ رمزگذاری‌شده همچنان نامعلوم است.
آزمون نمونهٔ خصوصی قبلی: ۴۹۵ فریم خروجی و ۵۰۳ ورودی در ۸ گروه مقصد؛ ۳۴۹۰۶ و ۲۱۷۹۴۶ بایت payload مشاهده‌شده؛ صفر فریم شواهد خوانا. این ضبط جدید نیست و نوع دادهٔ ارسالی را اثبات نمی‌کند. شرح QA در app/tests/QA-v2.7.md است.
کار باقی‌مانده: آزمون واقعی رابط/ضبط Windows 11، سازگاری PS5.1، بررسی محدودیت حجم/زمان لاگ و عیب‌یابی بر اساس UnifiedReport تازهٔ کاربر. هیچ ادعای پوشش کامل یا رمزگشایی TLS نشود.

# تاریخچه توسعه جلسه

## نیاز اصلی
کاربر ابزار اختصاصی Windows 11 خواست که یک EXE از مسیر مشخص، فرایندهای مرتبط، مقصدهای ارتباطی، DNS، سابقه ارتباط، مقصد تازه و گزارش CSV/JSON را یک‌جا نشان دهد. بعد خواست روشن شود چه اطلاعاتی از سیستم ارسال می‌شود. سادگی رابط، ترتیب روشن اجرا و یک اقدام اصلی از اولویت‌ها شدند. مخزن GitHub بعداً برای ادامه‌پذیری و انتقال اطلاعات معرفی شد.

## نسخه‌ها و علت تغییر
1. **v1:** WinForms/PowerShell، TCP snapshot، lineage از CIM، Sysmon اختیاری؛ گزارش و محدودیت پوشش. خروجی ابزار source/scripts بود، نه EXE مستقلِ ازقبل‌کامپایل‌شده. `Build-EXE.cmd` launcher را روی ویندوز می‌سازد و اسکریپت‌ها باید کنار آن بمانند.
2. **v2:** ضبط Pktmon، تبدیل ETL به PCAPNG، tshark، تطبیق tuple/time ±۵ ثانیه، تحلیل HTTP/HTTP2، SSLKEYLOGFILE اختیاری و مقایسه محدود شناسه‌های محلی. تطبیق زمان/tuple انتساب قطعی کرنلی نیست.
3. **v2.1:** دریافت ابزار رسمی، Wireshark x64/ARM64 با هش/امضای معتبر؛ نصب با رضایت؛ Npcap برای جریان Pktmon لازم نبود. Sysmon در بسته بازتوزیع نشد، مستقیماً دریافت و امضای Microsoft بررسی شد و سیاست موجود خودکار عوض نشد.
4. **v2.2:** مشکل framing پیدا شد: خروجی Pktmon فریم خام 802.11+LLC را Ethernet برچسب زده بود. تبدیل سخت‌گیرانه فقط برای قالب یکسان پشتیبانی‌شده و در کپی مشتق انجام شد؛ فایل اصلی تغییر نکرد. شمارنده قالب کلید، تطبیق ClientRandom و بررسی اثبات رمزگشایی اضافه شد.
5. **v2.3:** رابط ساده فارسی و اقدام اصلی ۹۰ ثانیه‌ای؛ آماده‌سازی، ضبط، اجرای هدف از Explorer با دسترسی معمولی، تحلیل خودکار و Reports-to-share. اجرای هدف با ادمین ممنوع شد. launcher-status برای تفکیک شکست اجرا از عدم تولید کلید اضافه شد.
6. **v2.3.1:** stderr tshark در Windows PowerShell 5 به NativeCommandError تبدیل می‌شد و warning دیسکتور X509AF گزارش را قطع می‌کرد. I/O باینری native در C# جدا شد؛ exit code واقعی کنترل و بسته‌های صریحاً نام‌برده warning از تفسیر کنار گذاشته شدند. warning رفع امنیتی/اصلاح upstream نشده؛ گزارش می‌تواند partial باشد.
7. **v2.4:** تشخیص فقط‌خواندنی EXE، PE imports و static markerها، فهرست محدود لاگ‌ها، بررسی اختیاری لاگ با شمارش کلمات ازپیش‌تعریف‌شده، بدون ذخیره مقدارها. نبود marker پشتیبانی TLS را رد نمی‌کند؛ وجود آن هم فعال‌بودن را ثابت نمی‌کند.
8. **v2.5:** رله HTTP/CONNECT محلی بدون CA یا رمزگشایی، تنظیم متغیرهای پروکسی فقط برای اجرای تازه هدف، انتساب PID/path، شمارنده بایت و گزارش سازگاری. عدم استفاده از env proxy، عدم سازگاری با همه روش‌های پروکسی را ثابت نمی‌کند.
9. **v2.5.1:** کاربر گفت لینک پایین پنجره بی‌واکنش است. در کد SW_HIDE و نبود startup acknowledgement وجود داشت. لینک به دکمه تبدیل شد، اجرای visible/STA، bootstrap، وضعیت Ready/Failed/Closed و timeout اضافه شدند. گزارش بعدی نشان داد آزمون پروکسی اجرا شده است.
10. **v2.6 آزمایشی:** کاربر تأیید کرد لانچر و صفحه ورود باز شدند؛ ورود کامل را آزمایش نکرد. اجازه آماده‌سازی بازرسی TLS با گواهی آزمایشی داد. mitmdump رسمی 12.2.3، بازرسی فقط telemetry-in.battle.net:443/SNI دقیق، عدم رمزگشایی حساب، رضایت جدا قبل از واردکردن CA در CurrentUser Root، پاک‌سازی دقیق، نگهبان مستقل، recovery و گزارش بدون مقدارها اضافه شدند.

## وضعیت آخر جلسه
- فایل‌های مرحله ۲٫۶ ساخته و آزمون‌های افزونه/محیط آزمایشگاهی انجام شدند؛ اجرای Windows 11 روی دستگاه واقعی هنوز نیازمند تأیید است.
- قرار است کاربر Start-TLS-Test.cmd را معمولی اجرا کند و تنها TelemetryReport را پس از بازبینی بفرستد.
- آماده‌سازی مرحله مجاز بود؛ این مجوز جای تأیید صریح هر اجرای گواهی در UI را نمی‌گیرد.
- هنوز فهرست کامل اطلاعات واقعاً ارسال‌شده به سرور مشخص نشده و ادعای جاسوسی/سرقت اثبات نشده است.
