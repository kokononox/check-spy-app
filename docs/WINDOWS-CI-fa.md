# آزمون ویندوز و ساخت بسته در GitHub

این گردش‌کار مشکل محیط آزمون ویندوز را هدف می‌گیرد؛ URL کامل یا بدنهٔ HTTPS بازی را بازیابی نمی‌کند.

## چه اجرا می‌شود؟

- بررسی نحوی اسکریپت‌ها و پنج فایل آزمون مصنوعیِ مشخص.
- دو اجرای مستقل روی Windows Server 2022: Windows PowerShell 5.1 و PowerShell 7 موجود روی runner.
- آزمون تحلیل capture، جهت رفت‌وبرگشت، جداکردن شواهد لاگ محلی، قالب تشخیصی کلید و هستهٔ ETW.
- ساخت ZIP کد و راهنمای ابزار مستقل ۲.۶.۵، فقط پس از موفقیت هر دو اجرای آزمون.

بازی، UI، trace، نصب گواهی و تغییر proxy اجرا نمی‌شوند. آزمون TLS فقط رشته‌های ساختگی دارد. نام workflow به معنی تأیید عملی روی بازی یا Windows 11 نیست.

## اجرا

پس از commit فایل‌ها، در مخزن به Actions برو و
`Windows synthetic validation and inspector package` را انتخاب کن.
با `Run workflow` اجرا کن. اگر هر دو آزمون موفق شوند، artifact شامل ZIP ابزار و SHA-256 خواهد بود.
گردش‌کار برای تغییر فایل‌های مربوط و pull request نیز اجرا می‌شود.

اگر workflow اجازهٔ اجرا نداشت، تنظیمات GitHub Actions و مجوز استفاده از دو action رسمی checkout و upload-artifact را بررسی کن. این کار به token شخصی یا secret اضافه نیاز ندارد؛ فقط دسترسی خواندن کد مخزن استفاده می‌شود.

## حریم خصوصی و حدود کار

هیچ EXE/DLL بازی، capture، ETL، گزارش کاربر، کلید یا لاگ خصوصی در این بسته یا ورودی CI قرار نده.
فایل‌های artifact با allowlist دقیق محدود شده‌اند. GitHub میزبان آزمون‌های ساختگی است، نه محل اجرای بازی یا آپلود دادهٔ حساس.
actionهای رسمی به commit ثابت متصل‌اند؛ هنگام ارتقا hash را از منبع رسمی تأیید کنید.

این workflow در محیط توسعه فقط از نظر ساختار، parser و آزمون‌های مصنوعی قابل‌اجرا کنترل شده است.
تا زمانی که نتیجهٔ Actions در ویندوز دریافت نشود، نباید آن را «آزموده‌شده روی ویندوز» نامید.

ساخت ZIP به معنی کامپایل EXE مستقل نیست. گردش‌کار هیچ release یا tag ایجاد نمی‌کند و به مخزن push نمی‌کند.
نسخهٔ اصلی مانیتور ۲.۷ حفظ شده و ابزار مستقل ۲.۶.۵ در مسیر tools قرار دارد.
