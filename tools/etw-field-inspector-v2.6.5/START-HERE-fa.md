# بررسی آفلاین رویدادهای قبلی — نسخهٔ آزمایشی ۲.۶.۵

هدف این مرحله: بفهمیم فیلدهای رویدادهای WinHTTP/WinINet چه ساختاری دارند و آیا نشانه‌ای از URL یا نام API در آن‌ها وجود دارد. این ابزار URL کامل یا محتوای ارسال‌شده را بازیابی نمی‌کند و TLS را رمزگشایی نمی‌کند.

## اجرا

۱. ZIP را در یک پوشهٔ جدید استخراج کن؛ جایگزین نسخه‌های قبلی نکن.
۲. با همان حساب ویندوزی که ضبط قبلی را انجام داد، `Inspect-ETW-Fields.cmd` را معمولی اجرا کن. لازم نیست بازی را دوباره اجرا کنی یا ضبط تازه بگیری.
۳. انتخاب پیشنهادی: فایل ETL نشست قبلی. در پنجرهٔ انتخاب فایل این مسیر را باز کن:

```text
%LOCALAPPDATA%\ExeRouteMonitor\Web-ETW
```

پوشهٔ نشست موردنظر را باز کن و فایل `.etl`، معمولاً `web-events.etl`، را انتخاب کن. فایل `process-observations-private.json` همان نشست باید کنار آن باشد. ابزار برای انتساب رویدادها به پردازش هدف از این فایل استفاده می‌کند؛ بدون آن تحلیل ETL متوقف می‌شود.

۴. رضایت بررسی محلی را تأیید کن. ابزار XML فیلدها و، اگر ویندوز بتواند بسازد، متن قالب‌بندی‌شدهٔ رویداد را فقط روی رایانهٔ خودت بررسی می‌کند.
۵. پس از پایان، پوشهٔ گزارش باز می‌شود. فقط فایل `EventFieldReport-....json` را پس از بازبینی برای بررسی بفرست.

مسیر گزارش قابل‌اشتراک:

```text
%LOCALAPPDATA%\ExeRouteMonitor\Reports-to-share
```

**فایل ETL، فایل process-observations-private.json یا private-target-events.jsonl را نفرست.** این‌ها ممکن است داده‌های خصوصی داشته باشند.

### اگر ETL موجود نیست

در فهرست نوع فایل پنجره، `Private target events` را انتخاب کن و فایل `private-target-events.jsonl` همان نشست را بده. این حالت متن قالب‌بندی‌شدهٔ ویندوز را ندارد، اما فیلدهای ذخیره‌شده را بررسی می‌کند. گزارش عمومی `WebTraceReport-....json` ورودی این ابزار نیست.

## گزارش چه چیزهایی دارد؟

- نام فیلدهای معمول، تعداد رویدادها و طول کمینه/بیشینهٔ مقدارها؛ نام‌های غیرمعمول حذف می‌شوند.
- نوع ظاهری مقدارها: عدد، GUID، متن، ساختار متنی یا کدگذاری احتمالی.
- تعداد رشته‌های شبیه URL؛ **نه تعداد درخواست‌های یکتا**.
- فقط نام‌های API از فهرست ثابت و مقصدهای شناخته‌شده از فهرست ثابت؛ آدرس‌های ناشناخته، مسیر کامل URL و query صادر نمی‌شوند.
- نشانه‌های احتمالی در نمایش hex/base64؛ این بررسی نمایش متن است، نه رمزگشایی TLS.
- خطاها، محدودیت‌ها و وضعیت دسترسی به متن قالب‌بندی‌شده.

متن خام فیلدها، متن خام پیام، توکن، هدر و بدنهٔ درخواست در گزارش ذخیره نمی‌شوند. بااین‌حال نام فیلدها، طول‌ها و نشانه‌های مقصد هم اطلاعات تشخیصی هستند؛ گزارش را قبل از اشتراک بازبینی کن.

## محدودیت‌ها

وجود نام API یا URL در پیام، اثبات فراخوانی آن API، ارسال درخواست، دریافت در سرور یا ارسال telemetry نیست. نبودن نشانه نیز اثبات نبودن ترافیک نیست. یک URL ممکن است هم در فیلد و هم در متن قالب‌بندی‌شده شمرده شود.

ویندوز ممکن است به‌دلیل نبود منابع پیام/manifest نتواند متن رویداد را بسازد؛ این به معنی خالی بودن داده نیست. انتساب پردازش همان محدودیت‌های ضبط قبلی را دارد.

سقف ورودی ۶۴ MiB و سقف پردازش ۱۰۰٬۰۰۰ ردیف/رویداد است. هر مقدار حداکثر تا ۶۵٬۵۳۶ نویسه بررسی می‌شود. محدودیت‌های دیگر در گزارش علامت می‌خورند. نتیجهٔ دارای خطا یا محدودیت را کامل تلقی نکن.

ابزار اینترنت، ضبط جدید، نصب گواهی، تغییر proxy یا اجرای بازی ندارد. فایل ورودی را تغییر نمی‌دهد. به Windows PowerShell 5.1 و محیط دسکتاپ ویندوز نیاز دارد.

## وضعیت آزمون

۲۴ آزمون مصنوعی هستهٔ تحلیل و عدم خروج مقدارهای خصوصی موفق شدند؛ چهار اسکریپت بدون خطای نحوی در PowerShell 7.4.7 لینوکس بررسی شدند. اجرای واقعی روی Windows PowerShell 5.1، رابط WinForms، ETL کاربر و FormatDescription هنوز آزموده نشده است. این بسته آزمایشی است و بازیابی URL کامل را تضمین نمی‌کند.
