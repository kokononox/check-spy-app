# کیت آزمایشی مشاهدهٔ پیش از رمزگذاری — ۰.۱

این کیت با ETW قبلی فرق دارد: برای مشاهدهٔ SECBUFFER_DATA در ورودی تابع SSPI EncryptMessage از دیباگر CDB استفاده می‌کند. طبق مستندات Microsoft، در کاربرد Schannel این بافر حاوی داده پیش از رمزگذاری است. اما EncryptMessage یک API عمومی SSPI است؛ کیت فعلی نوع context را Schannel تأیید نمی‌کند و موفقیت تابع یا ارسال روی شبکه را بررسی نمی‌کند. خروجی، «نامزد درخواست پیش از رمزگذاری» است، نه گواهی ارسال.

**این روش روی بازی آزموده نشده است. در اجرای آنلاین، حساب واقعی یا جلسهٔ دارای ضدتقلب از آن استفاده نکن.** دیباگر می‌تواند برنامه را متوقف کند، زمان‌بندی را تغییر دهد، اتصال را قطع کند یا توسط ضدتقلب رد شود. کیت هیچ ضدتقلب یا محافظتی را دور نمی‌زند؛ در صورت مخالفت/مسدودشدن، متوقف شو.

## شرط شروع

- محیط ویندوز آزمایشی جداگانه و برنامهٔ متعلق به خودت یا دارای اجازهٔ بررسی.
- بدون ورود به حساب واقعی و بدون اطلاعات مهم.
- برنامه و PowerShell هر دو x64.
- Microsoft Debugging Tools for Windows و CDB x64 از منبع رسمی نصب شده باشد. کیت چیزی را دانلود/نصب نمی‌کند و تغییر گواهی یا proxy ندارد.
- فایل خام می‌تواند URL کامل، query، Authorization/Cookie، رمز یا بدنه داشته باشد. هیچ فایل PRIVATE، raw log یا body را روی GitHub/Actions منتشر نکن.

اگر محیط جداگانه نداری، **فعلاً این کیت را روی بازی اجرا نکن**. دریافت اجازهٔ بررسی فایل‌ها، امکان اجرای واقعی بازی روی محیط Linux دستیار را ایجاد نمی‌کند.

## فایل‌های اصلی

- Prepare-Session.ps1: تأیید رضایت، بررسی EXE/PID، x64 و امضای CDB؛ فقط آماده‌سازی. خودش attach نمی‌کند.
- Debugger-Core.ps1: تولید دستور breakpoint و خواندن محدود خروجی db.
- Read-Private-Log.ps1: ساخت URLهای نامزد و گزارش امن از لاگ محلی.
- tests: آزمون مصنوعی و یک fixture متعلق به کیت؛ هیچ فایل بازی در آن نیست.

## مرحلهٔ ۱: آماده‌سازی فقط در محیط مجاز

برنامهٔ آزمایشی را خودت بدون حساب واقعی اجرا کن. PID آن را در Task Manager → Details ببین. در PowerShell x64، داخل پوشهٔ استخراج‌شده این دستور را با مقادیر واقعی خودت اجرا کن:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Prepare-Session.ps1 -TargetProcessId 1234 -TargetExe "C:\Test\WoW.exe" -CdbPath "C:\Program Files (x86)\Windows Kits\10\Debuggers\x64\cdb.exe"
```

`1234` و مسیر EXE فقط نمونه‌اند. دو تأیید `ISOLATED` و `PRIVATE` لازم است. ابزار فقط پوشهٔ خصوصی نشست و دستورهای دیباگر را می‌سازد. اجرای آماده‌سازی به معنی ثبت ترافیک نیست.

این نسخه به مسیرهای ASCII برای launcher محدود است. در صورت رد شدن مسیر/امضا/دسترسی، راه‌حل را تغییر تنظیمات امنیتی سیستم یا ضدتقلب قرار نده. خطا را بررسی کن.

## مرحلهٔ ۲: شروع و توقف دیباگر

در پوشهٔ خصوصیِ نمایش‌داده‌شده، `Attach-CDB.cmd` را باز کن. PID، زمان ایجاد و hash EXE دوباره بررسی می‌شوند. فقط پس از تأیید نهایی `ATTACH` دیباگر متصل می‌شود. بین آخرین بررسی و attach هنوز احتمال race وجود دارد؛ PID را همان موقع بازبینی کن.

کیت هیچ EXE هدفی را خودکار اجرا نمی‌کند و پردازش‌های فرزند را دنبال نمی‌کند. ثبت فقط در پردازش انتخاب‌شده انجام می‌شود. دیباگر برای breakpoint به‌طور موقت کد/اجرای هدف را تغییر می‌دهد؛ این «مانیتور منفعل» نیست.

حدود: ۶۴ ورود API، حداکثر ۱۶ KiB از هر بافر و مجموع ۲۵۶ KiB داده. با رسیدن به سقف، دستور پاک‌کردن breakpoint و detach صادر می‌شود. **سقف زمانی خودکار ندارد**؛ اگر ظرف حدود ۳۰ ثانیه نتیجه/توقف ندیدی، دستی متوقف کن. خطا یا آدرس خواندن نامعتبر می‌تواند هدف را در حالت توقف نگه دارد؛ سقف خودکار تضمین رهایی در همهٔ خطاها نیست.

برای توقف دستی، در پنجرهٔ CDB با Ctrl+C وارد prompt دیباگر شو، سپس:

```text
bc *
.logclose
.detach
q
```

فقط `q` نزن؛ در حالت عادی می‌تواند هدف را ببندد. کیت CDB را با `-pd` اجرا می‌کند تا احتمال بستن هدف در پایان کاهش یابد، اما جای detach صحیح و محیط جداگانه را نمی‌گیرد. اگر فرمان/اتصال رد شد، ادامه یا دورزدن محافظت را امتحان نکن.

Symbol پیش‌فرض `sspicli!EncryptMessage` است. فقط اگر بازبینی فنی نشان داد export دیگری لازم است، می‌توان در آماده‌سازی `-Symbol 'secur32!EncryptMessage'` داد. خودکار به چند breakpoint یا API دیگر تغییر مسیر نمی‌دهیم. صفر بافر می‌تواند ناشی از نبود/حل‌نشدن symbol، مسیر TLS دیگر یا نبود فراخوانی در این بازه باشد؛ اثبات نبود ارسال نیست.

## مرحلهٔ ۳: خواندن خروجی، فقط محلی

بعد از پایان و detach، داخل پوشهٔ کیت:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Read-Private-Log.ps1 -LogPath "C:\path\to\PRIVATE-cdb.txt"
```

خروجی local-results:

- PRIVATE-URL-candidates.json: URLهای نامزد با مسیر و query؛ فقط برای مشاهدهٔ خودت.
- Report-to-share.json: شمارنده‌ها و محدودیت‌ها؛ بدون URL، هدر، بدنه یا handle. فقط این فایل را بعد از بازبینی می‌توانی بفرستی.

اگر به ثبت بدنه در فایل محلی نیاز داری، گزینهٔ صریح `-SavePrivateBodies` را اضافه کن. فایل‌های body-*.bin خصوصی‌اند. لاگ اصلی از قبل ممکن است همهٔ این داده‌ها را داشته باشد؛ پیش‌فرضِ نساختن body.bin به معنی بی‌حساسیت بودن raw log نیست.

## حدود تفسیر

- HTTPS از Host و request-target فرض می‌شود؛ نوع context و destination socket تأیید نشده‌اند. URL مطلق در request-line با همین عنوان ثبت می‌شود.
- HTTP/1.x محدود پشتیبانی می‌شود؛ HTTP/2، HPACK، HTTP/3، chunked body، فشرده‌سازی و protobuf رمزگشایی نمی‌شوند.
- قطعات با handle یکسان به‌صورت محدود کنار هم گذاشته می‌شوند؛ handle reuse، retry، reordering و duplicate ممکن‌اند. بافر بریده‌شده کامل نامیده نمی‌شود.
- مشاهده در ورودی EncryptMessage، موفقیت رمزگذاری، ارسال socket یا دریافت سرور را ثابت نمی‌کند.
- بدنهٔ باینری حتی اگر ثبت شود، به schema و تشخیص envelope/encoding نیاز دارد؛ schema قبلی به‌تنهایی اثبات محتوای ارسال‌شده نیست.

## آزمون‌ها و وضعیت

۲۲ آزمون مصنوعی parser/command/privacy در PowerShell 7.4.7 روی Linux موفق شدند. این آزمون‌ها اجرای CDB یا بازی نیستند.

Test-CDB-Smoke.ps1 فقط fixture ساخته‌شده از سورس داخل کیت را آزمایش می‌کند: یک فراخوانی با context عمداً نامعتبر، بدون TLS handshake، شبکه یا اعتبارنامه. در نبود CDB صریحاً NOT RUN اعلام می‌شود. حتی موفقیت این fixture تأیید Schannel واقعی یا بازی نیست.
